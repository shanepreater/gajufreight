GajuFreight wireframes

Clickable low-fidelity screens for every party. They follow the user journeys in docs/ux/ and use the demo's fictional parties and route (shipment GF-2026-0008: three pallets, Yantian → Rotterdam → Tilburg).

Two ways to review the same screens

Locally: open this file (docs/wireframes/index.html) in any browser, or run npm run open --prefix scripts/wireframes. No server or install is needed.

Online: the private claude.ai review page shows the same screens and prompts, works on a phone, and takes comments. It's republished each round.

How to review

  1. Start with your own role below and follow the links as that person would.
  2. Ask whether each person can finish their job without help, and whether anything surprises them.
  3. Comment on the review page, or in the PR. The next round lands in both places.

Decisions for the reviewer in this round

  1. Booking and funding are two signatures. Keep them separate, or ask QPQ whether a contract can be funded as it's created?
  2. A missing package doesn't block the shipment. It's recorded and becomes dispute evidence. Should a scan with something missing need a second confirmation?
  3. Votes are visible to the whole panel. That helps arbiters converge but may anchor them. Show votes only after you've voted?
  4. Wording for "wrong stage" errors. Adopt "That isn't possible at this stage of the shipment" everywhere?
  5. New: every offer costs a network fee. Should the app suggest a round limit, or warn after, say, five counters?
  6. New: margins stay private. Leg carriers don't see the shipper's price, and the shipper doesn't see leg prices. Is that right for your customers?
